# เกณฑ์ตรวจ PR

รายการที่ผู้ตรวจอิสระไล่ดูทุก PR ก่อนตัดสิน
ข้อไหนไม่เกี่ยวกับ PR นั้นให้ทำเครื่องหมาย N/A ไม่ใช่ข้าม

## 1. ขอบเขตและเจตนา

- [ ] คำอธิบาย PR บอกได้ว่าแก้อะไร ทำไม และวัดผลยังไง
- [ ] diff อยู่ในขอบเขตที่อธิบายไว้ ไม่มีการแก้แถมที่ไม่เกี่ยวข้อง
- [ ] ไม่มีการเปลี่ยนพฤติกรรมที่ผู้ใช้เห็น โดยไม่ได้ระบุไว้ในคำอธิบาย
- [ ] ขนาด PR ตรวจได้จริง — ถ้าใหญ่เกินจนตรวจไม่ไหว ให้ขอแยก

## 2. ความถูกต้อง

- [ ] ตรรกะตรงกับที่คำอธิบายอ้าง — ไม่ใช่แค่ "ดูสมเหตุสมผล"
- [ ] เคสขอบ: ค่าว่าง, ศูนย์, ติดลบ, รายการเปล่า, timeout, ค่าซ้ำ
- [ ] error ถูกจัดการหรือส่งต่ออย่างตั้งใจ ไม่มีการกลืน exception เงียบ ๆ
- [ ] ไม่มีเงื่อนไขแข่งกันเวลา หรือสมมติฐานเรื่องลำดับที่ไม่มีอะไรรับประกัน

## 3. ความปลอดภัยและข้อมูล

- [ ] ไม่มี secret / token / คีย์ / รหัสผ่าน ปนอยู่ใน diff หรือประวัติ commit
- [ ] input จากภายนอกถูกตรวจสอบก่อนใช้ ไม่ต่อ query หรือคำสั่งด้วยการ concat string
- [ ] การตรวจสิทธิ์อยู่ฝั่งเซิร์ฟเวอร์ ไม่ได้พึ่งการซ่อน UI
- [ ] log ไม่บันทึกข้อมูลส่วนบุคคลหรือ credential
- [ ] dependency ที่เพิ่มเข้ามา: จำเป็นจริง มีคนดูแล และปักเวอร์ชันไว้

## 4. การทดสอบและหลักฐาน

- [ ] มีเทสต์ครอบคลุมพฤติกรรมที่เปลี่ยน ไม่ใช่แค่ทางเดินที่สำเร็จ
- [ ] เทสต์จะพังจริงถ้าย้อนโค้ดกลับ (ไม่ใช่เทสต์ที่ผ่านตลอด)
- [ ] CI ผ่านทั้งหมดบน commit ล่าสุด ไม่ใช่ commit ก่อนหน้า
- [ ] ถ้าไม่มีเทสต์ มีเหตุผลระบุไว้ และผู้ตรวจยอมรับเหตุผลนั้น

## 5. ความเสี่ยงเวลานำขึ้นระบบ

- [ ] การเปลี่ยนโครงสร้างข้อมูลย้อนกลับได้ หรือมีแผนย้อนกลับเขียนไว้
- [ ] ไม่ทำ interface พังสำหรับผู้เรียกใช้เดิม หรือแจ้งไว้ชัดว่าพัง
- [ ] ฟีเจอร์เสี่ยงมีสวิตช์ปิดได้โดยไม่ต้อง deploy ใหม่
- [ ] มีวิธีสังเกตว่าพัง — metric, log หรือ alert

## 6. ความเป็นอิสระของการตรวจครั้งนี้

- [ ] ผู้ตรวจไม่ได้เขียนหรือร่วมเขียนโค้ดใน PR นี้
- [ ] ไม่มีส่วนได้เสียที่ต้องเปิดเผย
- [ ] approve ผูกกับ commit ที่ตรวจจริง ไม่ได้ approve ล่วงหน้า

## การตัดสิน

| ผล | เมื่อไหร่ |
|---|---|
| **Approve** | ทุกข้อที่เกี่ยวข้องผ่าน ข้อสังเกตที่เหลือเป็นเรื่องความชอบ ไม่ใช่ความเสี่ยง |
| **Comment** | มีคำถามที่ต้องได้คำตอบก่อน แต่ยังไม่พบข้อบกพร่องชัดเจน |
| **Request changes** | พบข้อบกพร่อง ความเสี่ยงด้านความปลอดภัย หรือหลักฐานไม่พอให้ตัดสิน |

เมื่อไม่แน่ใจ ให้ถามก่อน approve — การอนุมัติที่ให้ไปแล้วมีน้ำหนักเท่ากับคำรับรอง
